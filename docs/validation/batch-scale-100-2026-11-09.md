# Batch workflow: one 100-item Linux validation

A later stage of the [Linux batch validation](batch-linux-2026-11-09.md) completed one fixed 100-item run on Ubuntu 24.04 with CPython 3.12.3. That earlier page records the checkpoint before this run; it remains historical. The experimental branch and private `0.3.0b3` package were unchanged during this stage. The installed wheel SHA-256 was `836b50d4dcda5f5b543256a20aae5edaa46c7172de37da8da108f4e333058cba`, with native extension SHA-256 `811fcb73e59727b13096c453a6a8f57c3e08e52957f9c0425f04363024f97d34`.

The run alternated **two byte-identical copies of one processed spectrum**, each with the same basename but a distinct path. It assigned 100 distinct item IDs and fresh output paths. Every item applied an empty operation list with the native backend, one thread and a 512 MiB application memory budget, then measured channel 0 with the same assignment template. The fixed 9 × 9 search and integration box used axis points `[1020, 1028]` and `[2044, 2052]`, positive sign, cutoff 1 and no baseline subtraction. No peak position, phase, scale, threshold or tolerance was fitted to the results.

**All 100 items completed serially.** The run retained 100 native files totalling 3,359,603,200 bytes, 100 ordered typed assignment rows and 102 sealed journal/report generations. Progress recorded at most one active item. Every row was `ambiguous` with four candidates and absent height and volume, as the independently frozen 81-point expectation required. The rows establish neither an assigned peak height nor an accurate physical volume.

An independent reviewer streamed the complete retained 3,413,596,160-byte archive (SHA-256 `c8ef1a4f2c9484f8fd9ca32fb438dedae03f9bf69d88532f678c24cdbf214643`) and checked its 534 original member pins. Each of the 100 native HDF5 files had the expected 33,596,032-byte container, all 8,388,608 stored float32 samples and the complete qualified scientific record. Across the run this covers 838,860,800 float32 values (3,355,443,200 sample bytes). The common sample SHA-256 was `709b199b07ede1a972092dc22de0c633cff69d95c9d4babecaa00d3909261784`; the reference record SHA-256 was `72e93df8f3e265cd25df9ee6e29f72e5c0d4ffc1310275b4f0417513ffb18316`. Exact axis records preserve all 6,144 coordinates per output under the earlier 0.00002 ppm axis qualification. The reviewer also checked every sealed generation's item and row coverage and typed CSV content.

The **50.72974-second elapsed time and 210,516 KiB peak resident memory** describe the entire one-run worker lifecycle, including startup, batch work and validation. They are diagnostic observations, not an application-only or aggregate memory figure and not a before/after speed or memory gain. The 512 MiB application budget and 2 GiB virtual address limit have different scopes from observed RSS.

This test repeated one already processed **real plane**, not 100 independent acquisitions. A prior legacy projection discarded the original full quadratures and some native annotations, metadata and provenance; this run could only preserve the imported representation. It does not test 3D/4D capacity, a real measured volume, the missing original-author processing workflow, independent end-user reopening or human/physical-machine acceptance. The guarded NMRPipe script importer still has its documented unsupported commands. The private wheel is unpublished; this validation does not promote the experimental workflow to stable v1.
