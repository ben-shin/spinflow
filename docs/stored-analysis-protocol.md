# Stored-spectrum analysis engineering protocol (S20)

This is a **post-failure engineering check on previously exposed data**, fixed before new acquired product analysis. It does not replace the failed S19 Bruker qualification, assert a new holdout or establish biological accuracy, raw-processing parity, phase accuracy, sensitivity or stable support. The source is the same Madison/BMRB bmse000002 acquisition already used in S19. Its original failure remains 50/56 checks, including six of 18 strict magnitude-window target failures. Human/physical-machine acceptance remains pending.

The [manifest](../benchmarks/cases/bmse000002-stored-analysis.json) retains the 19 original input URL/size/SHA-256 pins, all 18 deposited 1H targets and all four previously frozen HSQC rectangles and their four-component integrals. Acquisition binaries stay private; no redistribution licence is assumed. The new tool independently decodes the archived little-endian int32 `1r` and `2rr/2ir/2ri/2ii` files, retaining their recorded `2^-6` scale, full values and float64 precision. It requires the declared dimensions/layout and complete file lengths; it does not process the raw FID/ser. The existing public analysis API is unchanged.

## Fixed picker contract

Call actual `pick_peaks` once each on the full archived real 1H `1r` (32768 samples) and HSQC `2rr` (1024x1024 samples), as separate one-real-component Datasets. Parameters are `channel=0`, `sign="both"`, `threshold=None`, `snr=5.0`, `baseline="none"`, `min_separation=1.0`, `separation_unit="points"`, `max_peaks=10000`, with no detection/noise mask. No phase, window, baseline fitting, alignment, scaling, crop, interpolation or target-driven selection is added. Preserve every sign and every detected extremum, including those outside deposited target neighborhoods.

The independent oracle uses only standard Python and NumPy, not SciPy extrema/label helpers or product analysis helpers. Noise is the full-array amplitude median absolute deviation divided by the fixed normal constant `0.6744897501960817`. Threshold is five times that value. A point must be positive after multiplication by its tested sign, at least the threshold, and no smaller than any in-domain point within the 3-neighbor (1D) or 3x3 (2D) neighborhood. Connected equal-height local plateaus include diagonal connectivity; select the member nearest their arithmetic centroid, breaking exact ties lexicographically. A plateau needs an in-domain neighboring value strictly lower than its signed height; a constant array is not a peak. Domain-edge extrema are retained and flagged; multi-point plateaus are flagged. Sort by decreasing absolute original intensity, then lexicographic point, then positive sign first. At one-point strict axis-aligned exclusion distance distinct grid points cannot suppress each other. More than 50000 candidate plateaus, truncation above 10000 detections, malformed records or duplicate detection keys fail this check rather than silently dropping evidence.

Require exact complete ordered point/sign/intensity/flag agreement, report threshold/noise agreement and full input retention. Report all missed, extra, duplicate and differing detections. Derive physical coordinates independently from the archived header: `Hz=OFFSET*SF-index*SW_p/SI`, `ppm=OFFSET-index*SW_p/(SF*SI)`. Check every full-axis grid point and every detected coordinate with the existing `2e-5 ppm` absolute gate; Hz uses the same gate converted by that axis's recorded SF. No coordinate fit is allowed. Noise and threshold are compared exactly under these fixed float64 arithmetic conventions; a mismatch is retained as failure.

## Descriptive deposited-target lane

For all 18 1H targets, consider all positive actual detections with absolute ppm discrepancy strictly `<0.002`. Perform deterministic maximum-cardinality one-to-one bipartite matching: targets in document order; each target's eligible detections ordered by discrepancy then grid point; augmenting paths may reassign earlier targets. This maximizes count, not a fitted shift or a global minimum-error objective. Retain every target, eligible detection index, selected match/error, unmatched target and every unmatched positive or negative detection. The resulting matches are **descriptive**, not an acceptance criterion or a replacement of S19's magnitude-window test. No target can borrow the same detection as another target. A deposited list need not enumerate all physical spectral maxima, so unmatched detections are not labeled biological false positives.

## Fixed signed-volume lane

Use all four original nine-by-nine point rectangles and every archived component. Integrate their original physical ppm bounds with actual `integrate_regions(..., baseline="none")`. Independently sum each original cell's four scalar corners divided by four using `math.fsum`, then multiply by the absolute two-axis Hz cell area. Require exact agreement with the original frozen oracle anchors, and product relative discrepancy `<=1e-10`. Preserve signed integrals and absolute errors. A zero oracle or one whose absolute value is no greater than `1e-10` times its absolute-sample integral has an unusable denominator: record UNVERIFIED and fail the engineering gate. No `max(reference,1)` denominator, absolute-error fallback or sign cancellation repair is allowed. These mathematical rectangles and units establish no concentration, resolved peak volume or raw-to-reference quantitative equivalence.

## Controls, freeze and reporting

Analytical tests precede acquired invocation. Falsification must reject removed, added and duplicated detections, reversed sign, altered height/flags and shifted Hz/ppm; it must also reject an altered signed integral, zero/cancellation-dominated denominator, changed input/manifest/tool/protocol, unknown schemas and existing output paths. Synthetic equal plateaus, diagonal connectivity, edges, threshold equality and one-to-one ambiguity are explicit controls.

`prepare` hashes all 19 input files without decoding sample arrays, validates the manifest, and freezes the tool, protocol, manifest and actual Python/product/NumPy/SciPy module paths and hashes. Root must approve that lock before the first acquired product invocation. `run` verifies every identity, retains complete product/oracle records and all outcomes, and rechecks identities afterward. A changed lock or input requires a new recorded decision; never tune thresholds or repeat acquired work to obtain a pass. Reports refuse overwrite and retain execution errors as failures. The initial source-host run is Windows engineering evidence with exact runtime/source hashes, not an installed Linux or representative performance result. No timing/RSS or native-kernel claim follows from it.
