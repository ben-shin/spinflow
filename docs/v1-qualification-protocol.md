# Stage 19 qualification protocol

**Predeclared scope (2026-10-30):** advance the published experimental `v0.3.0b1` toward a future 1.0 decision through one bounded GUI figure repair, one frozen independent Bruker qualification case, and a lean Ubuntu researcher acceptance runner. The candidate version will be `0.3.0b2` while it is under review. A version number and automated pass do not establish stable 1.0 support or human acceptance. The source baseline is main `d467e467a091d32cfde8813e186364f6e214837f`; the `v0.3.0b1` release and older evidence are immutable.

| Gate | Requirement fixed before candidate results | Evidence to collect |
| --- | --- | --- |
| S19-GUI | **Save scientific figure** from a selected, applied Current region uses that exact bounded Dataset and compatible local peak/integral annotations. A parent-scale phase report remains separately available as analysis/workflow evidence. Refuse Original, Preview, stale/mixed region or report, and existing destination without changing prior state. Unselected figures retain the existing four-million-sample guard. | Failure-first small calibrated Hz/ppm and positive/negative-axis tests; actual 8,388,608-point parent to 201×201 local SVG/PNG figure; exact parent/local digest, coordinates, signed values and report linkage; bounded selected allocation; cancellation and failure checks. |
| S19-HOLDOUT | Freeze one new, independently chosen Bruker acquisition and expected checks before examining candidate output; retain source hashes, acquisition metadata, predicted axes/signs, limits and results. | Independent source/expected record, explicit numerical observations and refusals. One passing case does not generalize to every acquisition profile. |
| S19-HUMAN | Supply a lean Ubuntu desktop acceptance runner and blank researcher record, then have an actual user run it on the exact installed candidate and record observations. | Wheel/native/OS identity, researcher and source identity, applied/pending state, region/figure/CLI/export checks, failures, timings and verdict. Automation is preparatory evidence, not a human pass. |
| S19-DIST | Keep Python/native/installer/support-registry version records aligned at `0.3.0b2`; preserve old v0.2.0 and v0.3.0b1 artifact behavior. | Source checks, exact frozen archive/commit and build mapping, installed wheel tests and optional GUI/figure checks when an artifact exists. |

The GUI plot may remain sampled on large data; this stage does **not** implement adaptive viewport rendering. It does not change scientific algorithms, numerical tolerances, dataset/report formats, the 2M-point region analysis cap, the 4M-point figure cap, processing memory controls or support statuses. Qualify each gate PASS, FAIL or UNVERIFIED from its own exact source/artifact cohort. Keep old S18 evidence and releases unchanged. New private scratch belongs under `.artifacts/v1-qualification/`; never replace older sealed files. An integrated candidate is frozen before independent review; any post-freeze repair creates a distinct revision and receives focused retesting. No stable release, tag or broad compatibility claim follows automatically from this protocol.
