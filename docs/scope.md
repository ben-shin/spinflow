# Current implementation scope

The implementation targets synthetic 1D/2D workflows and controlled public Bruker and [Varian/Agilent](real-varian.md) raw paths through the headless CLI and optional Qt workbench. It includes explicit recorded-delay digital-filter correction, explicit frequency referencing and orientation, window, zero fill, FFT, manual phase, crop, reverse, transpose, native storage and declared interchange profiles. A bounded 1D complex and full-hypercomplex 2D automatic phase estimator, signed 1D/2D peak detection and relative region integrals produce digest-linked reports; optional Matplotlib figures do not become a core dependency. Explicit [analysis regions](analysis-regions.md) support phase, noise and baseline decisions. The GUI can save a native source plus a strict CLI recipe for replay of the last applied processing result. The [1D guide](real-bruker-and-analysis.md), [public 2D protocol](real-bruker-2d.md), [Linux user-testing guide](linux-user-testing.md), [roadmap](../ROADMAP.md) and [compatibility inventories](../compatibility/functions.yaml) retain the practical and broader future scope.

The synthetic complex/States mathematical model uses fully sampled axes. One public Bruker 1D acquisition with positive recorded `GRPDLY` has a bounded correction/archived-position check; two acquired public HSQC/TOCSY datasets additionally exercise fully sampled FnMODE 5/6, both-axis phase and fixed physical-region relative volumes. Two public Agilent acquisitions exercise a controlled 1D and a specific States 2D profile. Unknown/zero delay, implicit DSP lookup and broader vendor semantics remain unsupported. NUS reconstruction, broader automatic phase, automatic baseline correction, LP, deconvolved fitting, NEF and script translation remain visible future work. Unsupported requests fail. These cases do not satisfy the broader laboratory workflow exit of Milestone 1 because independent consumer reopening, NMRPipe parity and quantitative validation remain open.

Native means no NMRPipe subprocess; it does not mean every operation executes in C++. The declared Bruker correction and analysis are Python/NumPy/SciPy implementations, while the selected C++20/PocketFFT backend executes the FFT. Legacy numerical parity, NMRPipe benchmarks, real user-failure regression, all-format fidelity and broader platform installation claims remain blocked until evidence exists. The historical 1D TopSpin check covers eight peak positions. The separate 2D protocol checks acquired reference-array integration and raw relative volume ratios under a predeclared 30% tolerance; it does not establish concentration accuracy, absolute vendor parity or general consumer compatibility.
